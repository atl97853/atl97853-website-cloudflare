# Hook Classes

This document explains hook classes: what they are, why they are useful with reusable Astro components, when to use them, and when not to use them.

Hook classes are important because reusable components like `Card.astro` generate internal markup. A parent component may sometimes need to style that generated markup without changing the reusable component itself.

---

## 1. What is a hook class?

A hook class is a deliberate styling target.

It is a class added mainly so another stylesheet can safely reach a specific element.

In this project, hook classes are often passed through reusable component props such as:

```astro
class="..."
bodyClass="..."
listClass="..."
linkClass="..."
```

A hook class is not necessarily a new reusable component class. It may exist only to let one component target one generated element.

Example:

```astro
<Card bodyClass="c-pfp-card__body">
    ...
</Card>
```

Then:

```css
:global(.c-pfp-card__body) {
    align-items: center;
}
```

The hook class is:

```text
c-pfp-card__body
```

---

## 2. Why hook classes exist

Astro scopes component styles by default.

That means styles inside one component are rewritten so they match only that component's own markup. This prevents accidental leaks.

However, reusable components create markup internally.

Example:

```astro
<Card>
    ...
</Card>
```

The parent component does not directly write this internal element:

```astro
<div class="c-card__body">
    <slot />
</div>
```

`Card.astro` writes it.

So a local selector in the parent component like this may be unreliable or too dependent on Card's internal structure:

```css
.c-card--welcome .c-card__body {
    align-items: center;
}
```

A hook class solves this by intentionally passing a specific class to the generated element:

```astro
<Card bodyClass="c-pfp-card__body">
    ...
</Card>
```

Now the parent has a stable target:

```css
:global(.c-pfp-card__body) {
    align-items: center;
}
```

---

## 3. Why `:global()` is needed

If the hook class is applied to markup rendered inside another component, Astro scoped CSS may not reach it as a normal local selector.

So the parent component uses:

```css
:global(.c-pfp-card__body) {
    ...
}
```

This tells Astro:

```text
Do not scope this selector. Use this class exactly as written.
```

Even though `:global()` disables local scoping for that rule, the effect remains limited if the hook class is unique and only passed by that component.

---

## 4. The safety rule

A hook class is safe when it is:

```text
specific
intentional
documented
used by one component instance or one clear component pattern
not a generic Card.astro class
```

Good:

```css
:global(.c-pfp-card__body) { ... }
:global(.c-library-book__body) { ... }
```

Risky:

```css
:global(.c-card__body) { ... }
:global(.c-card .c-card__body) { ... }
```

The first examples target specific generated instances. The second examples target the reusable primitive itself and may affect every card.

---

## 5. When to use a hook class

Use a hook class when all of these are true:

```text
1. You need to style markup generated by a reusable component.
2. You cannot style the same thing through your own local wrapper.
3. The style is specific to this component instance or component pattern.
4. Changing the reusable component would affect too many other components.
5. Targeting the reusable internal class directly would be too broad.
```

Common cases:

- changing the internal Card body layout
- turning a Card body into a flex/grid container
- aligning slot children through `.c-card__body`
- adding a modifier to the generated body
- styling a generated element that does not exist directly in the parent template

---

## 6. When not to use a hook class

Do not use a hook class when you can style your own local markup.

Bad:

```astro
<Card bodyClass="c-blog-post__body">
    <div class="c-blog-post__content">
        <Content />
    </div>
</Card>
```

if the body class only does this:

```css
.c-blog-post__body {
    line-height: 1.72;
    overflow-wrap: break-word;
}
```

Better:

```astro
<Card class="c-blog-post">
    <div class="c-blog-post__content">
        <Content />
    </div>
</Card>
```

```css
.c-blog-post__content {
    line-height: 1.72;
    overflow-wrap: break-word;
}
```

No hook is needed because the component owns `.c-blog-post__content`.

---

## 7. Hook class vs local wrapper

Use a local wrapper first.

```astro
<Card title="Coursework">
    <div class="c-coursework">
        ...
    </div>
</Card>
```

```css
.c-coursework {
    max-width: 48rem;
    line-height: var(--lh-body);
}
```

Use a hook class only if the generated Card body itself must change.

```astro
<Card bodyClass="c-library-book__body">
    ...
</Card>
```

```css
:global(.c-library-book__body) {
    display: grid;
    grid-template-columns: 120px minmax(0, 1fr);
}
```

The difference:

```text
Local wrapper:
  Styles markup the component owns.

Hook class:
  Styles markup generated by another component.
```

## 8. Example: Pfp.astro

The profile/welcome card needs to align the children inside Card's body.

`Card.astro` renders the body:

```astro
<div class="c-card__body">
    <slot />
</div>
```

`Pfp.astro` needs this generated element to behave like a flex container with centered children.

Because the body belongs to `Card.astro`, the parent passes a hook class:

```astro
<Card
    title="Welcome to my website!"
    titleId="welcome-card-title"
    class="c-card--welcome"
    bodyClass="u-flex c-pfp-card__body"
>
    ...
</Card>
```

Then `Pfp.astro` targets the hook:

```css
:global(.c-pfp-card__body) {
    align-items: center;
}
```

This is valid because:

```text
The component needs to style generated Card body markup.
The class is specific to the Pfp card.
Card.astro stays unchanged.
Other Card instances are not affected.
```

---

## 9. Example: Library Book Entry

A library book entry needs the Card body to become a grid so the cover and content sit side by side.

Good:

```astro
const bookBodyClass = hasCover
    ? "c-library-book__body"
    : "c-library-book__body c-library-book__body--no-cover";

<Card
    as="article"
    class="c-library-book"
    bodyClass={bookBodyClass}
    ariaLabel={`Book: ${title}`}
>
    ...
</Card>
```

```css
:global(.c-library-book__body) {
    display: grid;
    grid-template-columns: 120px minmax(0, 1fr);
    gap: var(--space-md);
}

:global(.c-library-book__body--no-cover) {
    grid-template-columns: 1fr;
}
```

This is valid because the grid must apply to the generated Card body, not just an internal child.

---

## 10. Example: Blog post page

The blog post page does not need a body hook if it only styles the blog content.

Avoid:

```astro
<Card
    class="c-blog-post"
    bodyClass="c-blog-post__body"
>
    <div class="c-blog-post__content">
        <Content />
    </div>
</Card>
```

if `.c-blog-post__body` only sets typography.

Better:

```astro
<Card class="c-blog-post">
    <div class="c-blog-post__content">
        <Content />
    </div>
</Card>
```

```css
.c-blog-post__content {
    font-size: var(--fs-sm);
    line-height: 1.72;
    overflow-wrap: break-word;
}
```

This keeps the typography on markup owned by the blog page.

---

## 11. Example: Coursework page

The coursework page also does not need a Card body hook if the only styles are content width and line height.

Avoid:

```astro
<Card bodyClass="c-coursework-card__body">
    ...
</Card>
```

Better:

```astro
<Card title="Coursework">
    <div class="c-coursework">
        ...
    </div>
</Card>
```

```css
.c-coursework {
    max-width: 48rem;
    line-height: var(--lh-body);
}
```

The component owns `.c-coursework`, so no `:global()` is needed.

---

## 12. Naming hook classes

Hook classes should be specific.

Good:

```text
c-pfp-card__body
c-library-book__body
c-library-book__body--no-cover
```

Avoid:

```text
card-body
body-hook
special-body
custom-body
```

Use names that explain which component owns the hook, which generated element it targets, and whether it is a modifier.

Recommended pattern:

```text
c-[component-name]__body
c-[component-name]__body--modifier
```

Only use this pattern when the hook targets a generated body.

---

## 13. Avoid targeting Card internals directly

Avoid this:

```css
:global(.c-library-book > .c-card__body) {
    display: grid;
}
```

Prefer:

```astro
<Card bodyClass="c-library-book__body">
```

```css
:global(.c-library-book__body) {
    display: grid;
}
```

Why?

The hook class makes the relationship explicit. It says:

```text
This component intentionally styles this generated body instance.
```

A descendant selector says:

```text
Find Card's internal structure from outside.
```

The first is clearer and safer.

---

## 14. Hook-class comment template

When a hook class is not obvious, document it.

```css
/*
 * Card body hook
 *
 * Card.astro renders `.c-card__body`, so this component cannot safely rely on
 * a local descendant selector to style that generated element.
 *
 * This component passes `c-example__body` through Card's `bodyClass` prop and
 * targets it with `:global()` so the override applies only to this card body
 * instance.
 */
:global(.c-example__body) {
    ...
}
```

Longer explanation can live in the component front matter if the pattern is especially important.

---

## 15. Hook-class decision checklist

Before adding `bodyClass`:

```text
[ ] Do I need to style Card.astro's generated .c-card__body?
[ ] Can I solve this with a normal wrapper inside the Card instead?
[ ] Is this style changing the Card body structure, such as flex/grid/alignment?
[ ] Is the hook class component-specific?
[ ] Am I avoiding direct selectors like .c-card__body?
[ ] Is :global() limited to the hook class?
[ ] Have I documented why this hook exists?
```

If the answer to the second question is yes, use a local wrapper instead.

---

## 16. Common anti-patterns

### Broad Card body override

Avoid:

```css
:global(.c-card__body) {
    display: grid;
}
```

This affects every card.

### Wrapper class with no purpose

Avoid:

```astro
<Card class="c-logs-card" bodyClass="c-logs-card__body">
```

if neither class adds meaningful behavior.

### Hook for content typography

Avoid:

```astro
<Card bodyClass="c-blog-post__body">
```

if the style can be applied to:

```astro
<div class="c-blog-post__content">
```

### Styling Card internals through descendants

Avoid:

```css
:global(.c-card--welcome .c-card__body) {
    align-items: center;
}
```

Prefer:

```astro
<Card bodyClass="c-pfp-card__body">
```

```css
:global(.c-pfp-card__body) {
    align-items: center;
}
```

---

## 17. Summary

```text
Use local component classes whenever possible.
Use hook classes only for generated reusable-component markup.
Use :global() only on specific hook classes.
Do not target .c-card__body directly unless you are editing card.css itself.
Document hook classes because they are intentional exceptions to normal scoped CSS.
```
